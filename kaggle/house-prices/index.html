모델에 따라 인코딩이 달라진다

Ridge + OneHotEncoder

Ridge는 숫자 행렬의 선형 결합을 학습한다. 범주를 임의의 숫자 하나로 바꾸면 숫자 사이의 거리와 순서를 의미로 받아들일 수 있다.

OneHotEncoder는 범주마다 독립된 0/1 열을 만들어 이런 가짜 순서를 피한다. 수치형 열에는 스케일링도 적용한다.

HistGradientBoosting + OrdinalEncoder

OrdinalEncoder로 각 범주를 하나의 코드로 표현하고, categorical_mask로 어떤 열이 범주형인지 모델에 알려준다.

열 수가 크게 늘지 않아 트리 기반 모델에서 효율적이다.

CatBoost + 원래 범주

범주형 결측치만 "missing"으로 채우고 원래 컬럼 이름을 cat_features로 전달한다.

원핫이나 순서형 인코딩 없이 범주의 조합과 타깃 통계를 학습 과정 안에서 처리한다.

OrdinalEncoder의 0, 1, 2는 범주의 식별 코드다. 품질 순위를 뜻하지 않는다. 히스토그램의 bin을 만드는 과정은 모델 내부의 별도 동작이다.

두 모델의 기본 동작

Ridge

여러 특성의 가중합으로 집값을 예측한다. 큰 계수에 L2 페널티를 주어 과도한 적합을 줄인다.

예측 = 절편 + β₁x₁ + β₂x₂ + …

HistGradientBoostingRegressor

연속값을 구간으로 묶은 뒤 작은 결정 트리를 순서대로 추가한다. 각 트리는 앞선 예측의 오차를 줄이는 방향을 학습한다. 선형 모델보다 비선형 관계와 특성 간 상호작용을 자연스럽게 표현한다.

오류에서 배운 점

HistGradientBoosting 실험에서 실수로 Ridge용 전처리기를 연결하자 OneHotEncoder가 79개 원본 열을 더 많은 열로 확장했다. 반면 categorical_mask는 원래 전처리 결과를 기준으로 만들어져 길이가 맞지 않았다.

  1. 각 모델에 맞는 전처리기를 연결했는지 확인한다.
  2. 변환 후 열 수와 categorical_mask 길이가 같은지 확인한다.
  3. Pipeline으로 전처리와 모델의 조합을 하나의 단위로 관리한다.

복습: Ridge 전처리 Pipeline

숫자형은 중앙값 대치와 표준화, 범주형은 결측 범주 대치와 원핫 인코딩을 적용한다. ColumnTransformer가 두 결과를 합치고, 바깥 Pipeline이 전처리와 Ridge를 하나로 묶는다.

ridge_model = Pipeline([
    ("preprocess", ridge_preprocessor),
    ("model", Ridge(alpha=10.0, solver="lsqr")),
])
  • keep_empty_features=True: 학습 fold에서 전부 결측인 컬럼도 유지해 출력 차원과 범주형 마스크의 불일치를 막는다.
  • handle_unknown="ignore": 학습 때 없었던 범주가 검증 데이터에 나타나도 오류 없이 처리한다.
  • alpha=10.0: 계수 크기에 적용하는 L2 규제 강도다.
  • solver="lsqr": 원핫 인코딩으로 만들어진 희소 행렬에 적합한 반복 최소제곱 계산법이다.

최소제곱, MSE와 RMSE는 규제가 없고 평가 행이 같을 때 같은 예측을 최적점으로 선택한다. Ridge 학습에는 여기에 L2 규제 항이 추가된다.

복습: KFold와 OOF 예측

oof = np.full(len(X), np.nan)

for fold, (train_idx, valid_idx) in enumerate(splits, start=1):
    model.fit(X.iloc[train_idx], y.iloc[train_idx])
    prediction = model.predict(X.iloc[valid_idx])
    oof[valid_idx] = prediction

assert not np.isnan(oof).any()

kf.split(X)는 데이터가 아니라 학습 행과 검증 행의 위치 인덱스를 반환하므로 iloc으로 선택한다. 각 fold의 검증 예측을 oof[valid_idx]에 저장하면 모든 행이 자신을 학습하지 않은 모델로 한 번씩 예측된다.

처음에 NaN으로 채워두면 분할이나 대입 실수로 예측되지 않은 행을 마지막 검증에서 발견할 수 있다.

코드를 읽으며 해결한 작은 궁금점

2026-11-06 · 이번 기록은 문법과 모델 동작에 관한 복습이다. 새 실험을 실행하거나 점수를 추가한 것은 아니다. 낯선 축약 문법은 직접 외워 쓰기보다, 어떤 값이 전달되는지 읽을 수 있는 정도부터 익힌다.

CatBoost도 트리 기반 머신러닝인가?

CatBoost는 결정트리 여러 개를 순서대로 추가하는 그래디언트 부스팅 모델이다. 새 트리는 기존 예측의 오차를 줄이도록 학습한다. 분기 노드에서는 피처와 분기 기준을, 리프에서는 출력할 보정값을 학습한다. 신경망의 히든 레이어처럼 앞 트리의 출력을 다음 트리의 입력으로 전달하는 구조는 아니며, 예측할 때 각 트리의 출력을 합친다.

분기 조건은 면적 > 85처럼 읽을 수 있지만, 많은 트리와 범주 통계를 함께 사용하는 최종 예측 전체가 쉽게 설명되는 것은 아니다. 기본 대칭 트리에서는 같은 깊이의 노드들이 같은 분기 조건을 공유한다.

범주형 열만 사용하는가? 1,000번은 너무 많지 않은가?

학습에 제공할 열은 X로 정한다. cat_features=categorical은 그중 범주형으로 처리할 열을 알려줄 뿐, 수치형 열을 제외하지 않는다. 이 노트북의 HistGradientBoosting은 categorical_features=categorical_mask로 전처리 결과의 열 순서에 맞춰 범주형 위치를 표시한다. 역할은 비슷하지만 라이브러리별 인자 이름과 지원 형식은 다르다.

iterations=1000은 최대 부스팅 반복 수다. learning_rate=0.03처럼 보정을 조금씩 반영하면 더 많은 트리가 필요할 수 있으므로 횟수만으로 과도하다고 판단하지 않는다. 검증 오차와 학습 시간을 함께 확인한다. 조기 종료를 비교한다면 기존 고정 조건 실험과 구분하고, 검증 결과를 반복 활용하는 선택 편향도 기록한다.

dict, *, **는 어디에 쓰였는지 함께 읽기

params = dict(iterations=1000, depth=6)
# {"iterations": 1000, "depth": 6}과 같다.

CatBoostRegressor(**params)
# CatBoostRegressor(iterations=1000, depth=6)과 같다.

experiment_params = {**params, "depth": 8}
# 새 딕셔너리: 뒤의 depth=8이 우선하며 원본은 그대로다.

func(*[10, 20])
# func(10, 20): 값을 위치 인자로 펼친다.

func(**{"a": 10, "b": 20})
# func(a=10, b=20): 이름과 값을 키워드 인자로 펼친다.

**는 함수 호출에서는 키워드 인자로, 딕셔너리 안에서는 항목으로 펼친다. 별개의 문맥이므로 규칙도 다르다. {**params, "depth": 8}은 덮어쓰지만 CatBoostRegressor(**params, depth=8)은 같은 인자를 중복 전달해 오류가 난다. 함수 정의의 def func(**kwargs):는 반대로 키워드 인자들을 딕셔너리로 모은다. *로 펼칠 대상은 리스트에 한정되지 않고 반복 가능한 객체다.

설정 딕셔너리는 여러 모델 생성이나 실험 설정 재사용에 편리하다. 한 번만 사용하는 경우에는 생성자에 인자를 직접 적어도 된다.

lambda, factory, clone은 왜 함께 나오는가?

estimator_factory=lambda: CatBoostRegressor(**catboost_params)

# 전달한 lambda는 아래 함수와 같은 역할이다.
def make_model():
    return CatBoostRegressor(**catboost_params)

# 평가 함수 내부의 조건식을 풀어 쓰면:
if estimator_factory is not None:
    fold_estimator = estimator_factory()
else:
    fold_estimator = clone(estimator)

lambda:는 인자를 받지 않는 함수를 만든다. 이 함수를 전달하는 순간에는 모델을 만들지 않고, estimator_factory()를 호출할 때마다 새 모델을 만든다. 생성자 호출은 설정된 객체를 만들며 실제 학습은 fit()에서 시작한다.

factory는 모델을 만드는 함수를 호출하고, clone은 전달받은 모델과 설정이 같은 미학습 모델을 만든다. 둘 다 fold마다 이전 학습 결과 없이 시작하려는 목적이다. CatBoost가 원래 clone을 지원하지 않는 것은 아니다. 다만 CatBoost 1.2.10에서 cat_features 같은 변경 가능한 인자가 있을 때 clone이 실패하는 호환성 문제가 보고됐다. 이 노트북의 저장된 환경 출력도 1.2.10이며, 생성자를 직접 호출하는 factory는 그 경로를 피할 수 있다. 이 문서화 작업에서 오류를 재현한 것은 아니다.

반복 수와 조기 종료 비교 — 실험 마무리

2026-11-07 · 사용자가 실행해 공유한 fold별 출력과 반복 수를 정리했다. 문서 작성 과정에서 재학습하지 않았다. 기존 CatBoost의 피처·전처리·5-fold 분할·seed·깊이 6·학습률 0.03을 유지하고 반복 수와 조기 종료를 비교하는 실험이다. 실행 환경은 기존 Python 3.12, CatBoost 1.2.10이며, seed는 노트북의 SEED 설정을 따른다.

데이터는 Kaggle House Prices의 공식 학습 데이터다. 지표는 기존 로그 변환 타깃과 예측 간 RMSE이며 낮을수록 좋다. 아래 fold 평균은 각 fold RMSE의 산술평균으로, 전체 OOF 예측으로 계산한 RMSE와 구별한다. 평균과 시간 합계는 공유된 표의 반올림된 값으로 집계했다.

1,000회 고정 실행의 시간은 이번 비교에서 공유된 452.94초를 사용했다. 앞선 첫 실험의 346.09초와는 별도 실행이다. 실행 당시 부하에 따라 시간이 달라지므로 반복 수 변화만으로 시간 차이를 모두 설명하지 않는다.

최고 성능 반복은 1부터 센 횟수다. use_best_model=True로 최종 저장 트리 수는 표의 최고 성능 반복 수와 같다. 1,000회 상한에서는 fold 3만 조기 종료됐다. 2,000회 상한에서는 모든 fold가 최고 성능 이후 100회 동안 개선되지 않아 종료됐으며, 실제 반복 수 합계는 6,596회였다. 이는 2,000회씩 모두 실행하는 10,000회보다 약 34% 적지만, 같은 비율의 시간 절약을 측정했다는 뜻은 아니다.

구현하면서 해결한 점과 평가 한계

  • eval_set은 현재 fold의 검증 입력과 정답을 담은 튜플이다. valid_idx를 알 수 있는 평가 함수의 반복문 안에서 fit()에 전달했다.
  • 입력은 features.iloc[valid_idx]로 선택하고, NumPy 배열인 정답은 y[valid_idx]로 선택한다. 배열에는 .iloc이 없다.
  • 공통 평가 함수에서 eval_set, early_stopping_rounds, use_best_model은 CatBoost에만 전달한다. Ridge Pipeline에는 전달할 수 없다.
  • 추가 데이터 분할과 재학습 비용을 피하려고 OOF 검증 fold를 조기 종료에도 사용했다. 학습 데이터 양은 유지했지만, 같은 검증 정답으로 반복 수를 선택하고 평가하므로 점수가 낙관적일 수 있다.
  • 이 결과는 고정 반복 수 실험과 완전히 같은 평가 조건이 아니다. 검증 결과를 보며 반복 수를 조정한 선택 편향도 있으며, 독립된 최종 평가로 일반화 성능 개선을 확인한 것은 아니다.
이번 실험은 여기서 마무리한다. 500회는 1,000회 고정보다 시간을 약 51.7% 줄였지만 OOF RMSE가 약 2.6% 증가했다. 1,000회 상한의 조기 종료는 총시간을 약 7.9% 줄이는 데 그쳤다. 상한을 2,000회로 높이면 fold 3 외에는 추가 학습으로 점수가 개선됐지만, 1,000회 조기 종료 대비 시간은 약 43.0% 늘고 fold RMSE 평균은 약 0.78% 낮아졌다. 조기 종료의 가치는 항상 빨라지는 데 있지 않고, 충분한 상한 안에서 fold별로 학습량을 조절하는 데 있었다.

이번 관측에서는 1,000회가 충분한 상한이 아니었다. 반대로 100회 동안 개선이 없었다고 이후에도 절대 개선되지 않는다는 보장은 없다. 2,000회를 보편적인 최적값으로 단정하지 않으며, 추가 튜닝은 진행하지 않는다.

Lasso: 모델보다 먼저 규제 강도를 확인하기

2026-11-07 · Ridge의 설정을 참고해 Lasso(alpha=10.0)을 적용했더니 OOF RMSE가 0.399576으로 크게 나빠졌다. 원인을 확인하기 위해 기존과 같은 데이터, 피처, 전처리, 5-fold 분할(seed 42)을 유지하고 규제 강도만 비교했다.

타깃은 np.log(SalePrice)이며 평가는 전체 OOF 예측의 로그 RMSE다. 수치형은 중앙값 대치와 표준화, 범주형은 결측 문자열 대치와 원핫 인코딩을 Pipeline 안에서 각 학습 fold에만 fit했다. 확인 실행에는 사용자 노트북과 같은 Python 3.12.9 / pandas 2.3.3 / scikit-learn 1.9.1 환경을 사용했다.

Lasso 두 설정은 모두 max_iter=10000으로 실제 실행해 확인했으며 수렴 경고는 없었다. Ridge는 앞선 기록을 비교 기준으로 사용했다. 계수 수는 원핫 인코딩 후 피처 기준이며, fold마다 등장하는 범주에 따라 전체 피처 수도 달라질 수 있다.

왜 같은 가격만 예측했나?

Lasso의 L1 규제는 계수를 정확히 0으로 만들 수 있다. 이번 데이터에서 alpha=10은 너무 강해서 모든 피처의 계수가 0이 됐고, 절편만 남았다. 따라서 각 fold에서 모든 검증 집에 학습 fold의 평균 로그 집값을 예측했다. 평균만 예측하는 기준 모델과 점수가 같은 이유다.

규제를 0.001로 낮추자 일부 피처의 계수가 남아 집의 특징에 따라 다른 가격을 예측하게 됐다. 모델 자체가 나쁘다고 판단하기 전에, 설정 때문에 피처를 전혀 활용하지 못하는지 확인해야 한다는 것을 배웠다.

lasso_model = Pipeline([
    ("preprocess", lasso_preprocessor),
    ("model", Lasso(
        alpha=0.001,
        max_iter=10000,
    )),
])

alpha는 규제 강도이고 max_iter는 최적화 계산에 허용하는 최대 반복 수다. CatBoost의 트리 개수와 같은 의미는 아니다. Ridge와 Lasso는 규제 방식뿐 아니라 오차 항의 정규화도 달라서 같은 alpha=10을 같은 규제 강도로 해석할 수 없다.

이번 결론은 “Lasso가 좋지 않다”가 아니라 “현재 데이터와 전처리에서 alpha=10의 규제가 지나치게 강했다”이다. 전처리·검증 코드는 유지하고, 계수와 평균 예측 기준을 확인해 원인을 찾았다.

0.001은 문제 원인을 확인하기 위해 비교한 값으로, 최적값을 찾은 결과가 아니다. 같은 검증 결과를 보며 설정을 선택하면 선택 편향이 생기므로, Ridge보다 조금 낮은 점수만으로 일반적인 우위를 단정하지 않는다. 이번 확인에서 학습 시간은 별도로 기록하지 않았다.
